# Slot Hero 팝업 · 오버레이 코드

인게임 화면 기획서 v0.2 의 08 화면 팝업, 14 진행 중 팝업,
그리고 13 현재 빌드 화면 의 아이템 상세 팝업을 옮긴 코드다.

08장이 "런 진행 중이 아닐 때 출력하는 팝업의 공통 틀이다. 14장의 진행 중 팝업도 이 틀을 따른다"로
두 장을 한 틀로 묶었으므로 여기서도 하나로 만들었다.

저장소를 받으면 이 `Popup` 폴더를 통째로 `Assets/Scripts/Popup`으로 옮기면 된다.

## 파일 구성

```
Popup/
  Runtime/
    Data/
      PopupSpec.cs            팝업 하나에 담을 것. PopupButtonSpec 도 여기 있다
      PopupLayoutMath.cs      버튼 개수에 따른 배치 규칙. 폭과 간격은 속성이라 좌표 배율을 탄다
      ItemDetailSpec.cs       아이템 상세 오버레이에 적을 것
    Config/
      PopupLayoutConfig.cs    자리와 크기. ScriptableObject
      PopupVisualConfig.cs    색과 글자. ScriptableObject
    UI/
      PopupButtonView.cs      팝업 버튼 하나
      PopupView.cs            팝업 하나의 표시
      PopupPresenter.cs       팝업을 띄우고 닫는 창구
      ItemDetailView.cs       아이템 상세 오버레이
```

그래서 자리와 강조색을 따로 두었다.

## 자리와 크기

본체와 버튼 규격은 기획서가 정한 값이고, 나머지는 와이어프레임 실측을 10 단위로 옮긴 것이다.

| 항목 | 값 |
| --- | --- |
| 본체 | 1080 폭, 세로는 본문에 따라 줄어든다. 최대 820 |
| 본체 안쪽 여백 | 좌우 40, 위 60, 아래 40 (실측 좌우 41) |
| 제목 칸 | 1000 × 80 (실측 998 × 76) |
| 제목과 본문 사이 | 30 |
| 본문과 버튼 사이 | 40 |
| 버튼 칸 높이 | 100 (실측 97) |
| 아이템 상세 | 500 × 380 |

제목과 버튼과 여백이 차지하는 세로가 350이므로 본체 높이는 350 더하기 본문 높이가 된다.
본문 400을 넣으면 750이 나온다. 와이어프레임 실측은 본문 396에 본체 739였다.
본문이 가질 수 있는 최대는 820 빼기 350인 470이고 그보다 길면 본문 안에서만 스크롤한다.

제목 칸 폭이 1000이 되어 버튼 줄 980이 좌우로 10씩 남기고 들어간다.

색은 다음과 같다.

| 자리 | 색 |
| --- | --- |
| 팝업 본체 | `#FCFCFC` |
| 제목 칸 | `#F2F0EC` |
| 본문 칸 | `#D9D9D9` |
| 평범한 버튼 | `#F2F0EC` |
| 강조 버튼 | `#9E2B25` |
| 강조 버튼 글자 | `#FFFFFF` |
| 아이템 상세 본체 | `#F1EFEA` |
| 아이템 상세 안쪽 칸 | `#E4E0D8` |

강조 버튼 색은 04 화면 공통 규칙 의 텍스트 표에 적힌 값과 정확히 같다.
글자 크기와 색도 그 표를 그대로 쓴다.
제목 40픽셀 굵게, 본문 24픽셀, 버튼 30픽셀 굵게,
아이템 이름 30픽셀 굵게, 가치 24픽셀 굵게, 플레이버 20픽셀이다.

## 붙이는 법

### 1. 설정 에셋을 만든다

프로젝트 창에서 우클릭 후 `Create > Slot Hero > 팝업`에서 두 개를 만든다.

- 팝업 자리 설정 (`PopupLayoutConfig`)
- 팝업 표시 설정 (`PopupVisualConfig`)

### 2. 씬을 만든다

```
Popup                      PopupPresenter, 팝업 루트
  Dim                      Image · 뒤 화면을 덮는 막, Raycast Target 켬
  PopupPanel               PopupView, Image
    TitlePanel             Image
      TitleLabel           TMP_Text
    BodyPanel              Image
      BodyScroll           ScrollRect · 세로만 켠다
        BodyViewport       Mask 또는 RectMask2D
          BodyContent      TMP_Text
    ButtonLayer            빈 RectTransform. 버튼이 여기 아래에 만들어진다

ItemDetail                 ItemDetailView
  Root                     Image · 안쪽 배치는 프리팹에서 맞춘다
```

버튼 프리팹은 루트에 `PopupButtonView` + `Button` + 배경 `Image`,
자식에 `TMP_Text` 하나를 둔다.

팝업은 04 화면 공통 규칙 의 레이어 순서로 아래 레이어를 조작할 수 없게 막는다.
그래서 `Dim` 의 Raycast Target 을 켠다.
아이템 상세는 오버레이라 아래를 막지 않으므로 Raycast Target 을 끈다.

### 3. 호출

```csharp
// 새 게임 확인
PopupSpec spec = PopupSpec.Confirm(
    "새 게임을 시작하시겠습니까?",
    "진행 중인 런이 사라집니다. 되돌릴 수 없습니다.\n\n" + savedRunSummary,
    "돌아가기",
    "새 게임 시작",
    confirmIsDangerous: true);

popup.Show(spec, buttonId =>
{
    if (buttonId == "confirm")
    {
        game.StartNewRun();
    }
});

// 런 종료 확인. 가운데가 강조색이다
PopupSpec endRun = new PopupSpec("런을 끝내시겠습니까?", string.Empty);
endRun.Add(PopupButtonSpec.Normal("cancel", "취소"));
endRun.Add(PopupButtonSpec.Danger("abandon", "런 포기"));
endRun.Add(PopupButtonSpec.Normal("save", "저장하고 나가기"));
popup.Show(endRun, OnEndRunChosen);

// 아이템 상세. 커서가 물건 위에 올라갔을 때
itemDetail.Show(
    new ItemDetailSpec("바다 은화", "일반", "체력 10\n예측 성공 시 +5", "은은 파도에도 쉽게 녹슬지 않는다."),
    cursorPosition);

// 벗어나면 지운다
itemDetail.Hide();
```

### 게임에서는 흐름이 잇는다

2026년 10월 5일까지 이 오버레이는 **씬에 놓이지도 않았고 아무도 부르지 않았다.** 원재가 안 보인다고 짚어 이었다.

- 확인용 씬 `08 아이템 상세` 에서 만들어 게임 씬으로 가져온다. 현재 빌드 위, 설정과 팝업 아래다.
  껍데기 `ItemDetail` 은 캔버스를 꽉 채우고 늘 켜 둔다. 켜고 끄는 것은 안쪽 `Root` 다
- `GameFlowController` 가 세 곳의 커서 알림을 받아 띄운다.
  행상 진열(`SanctumController.ItemDetailRequested`), 보상 카드(`RewardScreenController.CardHoverChanged`),
  현재 빌드 칸(`CurrentBuildScreenController.SlotHoverChanged`)
- 적을 내용은 `Flow/Runtime/ItemDetailTexts` 가 물건 목록에서 만든다.
  문양은 우상단에 가치(태그 가치 합), 내용에 태그 둘을 적고 코인과 유물은 우상단에 희귀도를 적는다.
  **물건마다의 효과 설명과 플레이버 텍스트는 아직 없다.** 문양, 코인, 유물 기획서 소관이다
- 떠 있는 동안 매 프레임 커서를 따라간다(`ShowAtCursor`, `Update`). 화면이 바뀌면 흐름이 지운다
- 그림과 글자 모두 커서를 받지 않는다. 받으면 커서가 오버레이로 넘어가 물건에서 벗어난 것으로 읽혀 깜빡인다

## 버튼 칸은 돌려 쓴다

`PopupView` 는 버튼 칸을 한 번 만들면 다음 팝업에서도 그대로 쓴다.
버튼이 적은 팝업이 뜨면 남는 칸을 끄고, 많은 팝업이 뜨면 모자란 만큼 새로 찍어 낸다.

**끈 칸을 다시 켜는 것을 빠뜨리면 안 된다.**
버튼 하나짜리 팝업이 한 번 뜨고 나면 그 뒤에 뜨는 버튼 셋짜리 팝업에서
첫 하나만 보였다. 런 종료 확인 팝업이 그랬다.
`BuildButtons` 가 `Bind` 하기 전에 `SetActive(true)` 를 부른다.

게임 씬 검사가 **셋 → 하나 → 셋** 순서로 띄워 본다.
이 순서가 아니면 잡히지 않는다.

## 검증 결과

유니티 없이 순수 로직만 따로 빌드해 66건을 확인했고 전부 통과했다.

- 버튼 하나는 폭 450 가운데, 둘은 폭 450 간격 80, 셋은 폭 300 간격 40으로 기획서와 같다.
  이 넷은 `const` 가 아니라 속성이다. `const` 로 두면 좌표 배율이 곱해지지 않는다.
  배율이 12 였을 때 화면에서 버튼이 12분의 1로 쪼그라든 적이 있다
- 둘과 셋은 전체 폭이 980으로 같고 좌우 대칭이며 본문 폭 1000 안에 들어간다
- 제목과 버튼과 여백이 350이라 본문 400이면 본체가 750이 된다
- 내용이 적으면 본체가 짧아지고, 본문 최대 470을 넘으면 스크롤이 필요하며,
  아무리 길어도 본체는 820을 넘지 않는다
- 새 게임 확인은 오른쪽이, 런 종료 확인은 가운데가 강조색이고 자리도 맞는다
- 아이템 상세가 커서 오른쪽에 붙고 화면 네 가장자리를 넘지 않는다
- 색이 와이어프레임과 04 화면 공통 규칙 표에서 뽑은 값과 같다

## 기획서와 와이어프레임이 어긋나는 곳

**런 종료 확인 팝업이 공통 틀을 따르지 않는다.**
08장은 "14장의 진행 중 팝업도 이 틀을 따른다"로 정했는데
와이어프레임의 런 종료 확인 팝업은 본체가 700 × 320이고 버튼이 196 폭에 간격 24다.
공통 틀의 1080 폭, 버튼 300 폭, 간격 40과 다르다.

기획서 본문을 따라 공통 틀로 만들었다.
작은 팝업을 따로 두려면 알려 주면 넣겠다.

**새 게임 확인 팝업의 버튼이 기획서 수치와 조금 다르다.**
기획서는 폭 450에 간격 80인데 와이어프레임은 폭 461에 간격 76이다.
본문 폭 998을 꽉 채우려고 늘린 것으로 보인다.
기획서 수치를 따랐고 그 결과 버튼 줄이 980이 되어 좌우로 9씩 남는다.

**아이템 상세 팝업의 노드 이름이 실제 크기와 다르다.**
와이어프레임 노드 이름은 "아이템 상세 팝업 · 500 × 500"인데 실제 크기는 500 × 380이다.
기획서 본문이 500 × 380이므로 그쪽을 따랐다.

## 기획서에 없어 내가 정한 부분

확인이 필요하면 알려 주면 고친다.

1. **버튼 줄의 가로 자리** 기획서는 폭과 간격만 정했다.
   버튼 줄 전체를 본체 가운데에 맞췄다.
2. **커서에서 띄우는 거리** 아이템 상세를 커서의 오른쪽 아래로 24씩 띄웠다.
3. **가장자리 여백** 아이템 상세가 화면 가장자리에서 40을 남긴다.
   04 화면 공통 규칙 의 안전 영역 40을 가져온 것이다.
4. **팝업 버튼의 밝기 변화** 04 화면 공통 규칙 의 버튼 상태를 가져와
   마우스를 올리면 10퍼센트 밝게, 누르면 10퍼센트 어둡게 한다.
5. **본문 높이를 재는 방법** 글자가 차지할 높이를 재서 본체 세로를 정한다.
   본문 칸 안쪽 여백은 와이어프레임의 32를 썼다.

## 이 코드에 없는 것

- 어떤 팝업이 언제 뜨는지. 각 화면이 정해 `PopupSpec` 을 넘겨 준다
- 팝업에 적을 글. 저장된 런의 요약 같은 내용은 그 시스템이 만들어 넘긴다
- 아이템마다의 이름과 내용과 플레이버 텍스트. 문양, 코인, 유물 기획서 소관이다
- 자동 저장 표시. 같은 오버레이지만 04장 고정 자리라 `Hud` 폴더에 있다
- 상단 표시줄의 현재 방 설명. `TopBar` 폴더의 호버 팝업이 맡는다
