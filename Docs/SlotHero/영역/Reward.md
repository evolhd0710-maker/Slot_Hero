# Slot Hero 보상 화면 코드

인게임 화면 기획서 v0.2 / 10 보상 화면 을 옮긴 것이다.
전투나 이벤트를 끝낸 뒤 보상을 고르는 화면이다.

## 파일 구성

```
Reward/
  Runtime/
    Data/
      RewardOffer.cs         보상 한 벌. 골드 둘과 카드 목록
      RewardCard.cs          카드 하나. 문양·코인·유물
      RewardText.cs          골드 액수와 태그 줄을 만든다
    Config/
      RewardLayoutConfig.cs  자리와 크기. ScriptableObject
      RewardVisualConfig.cs  색과 글자. ScriptableObject
    UI/
      RewardCardView.cs      카드 한 장
      RewardScreenView.cs    화면 배치와 표시. IRewardIconSource 도 여기 있다
      RewardScreenController.cs  고르고 닫는 흐름
```

## 기획서 대응표

| 기획서 | 코드 |
| --- | --- |
| 보상 박스 · 획득 항목을 묶어 배치 | `BoxPosition`, `GetBoxSize` |
| 기본 보상 · 이름과 골드 아이콘과 액수 | `BaseGoldPosition`, `BaseGoldText` |
| 오버킬 보상 · 기본 보상 아래 | `OverkillGoldPosition` |
| 오버킬 골드가 없으면 그 줄은 비워 둔다 | `RewardOffer.HasOverkill` |
| 보상 카드 300 × 300 | `CardSize` |
| 화면 가운데에 가로로 배치 | `GetCardPosition` |
| 선택한 카드만 강조 | `RewardVisualConfig.GetCardColor`, `RewardCardView.SetSelected` |
| 해당 아이템의 주요 정보를 표시 | 그림, 이름, 문양이면 태그 둘 |
| 건너뛰기 · 보상 박스 아래 | `SkipPosition`. 지금은 "아이템 선택 건너뛰기" 와 "보상 받기" 로 바뀌는 아래 버튼이다 |
| 카드 입력 시 즉시 획득하고 화면을 종료 | **바꿨다.** 카드는 골라 두고 아래 버튼으로 받는다. 아래 "카드 고르기" 를 본다 |
| 마우스 호버 시 아이템 상세 | `CardHoverChanged`. 띄우는 쪽은 팝업 영역이 맡는다 |
| 카드 크기는 유지하고 박스 가로 폭만 늘린다 | `GetBoxSize(cardCount)` |

## 와이어프레임에서 잰 값

값은 전부 10 단위로 맞췄다. 괄호 안이 실측값이다.

| 무엇 | 자리와 크기 |
| --- | --- |
| 보상 박스 | 410, 180 · 1100 × 660 (412, 182 · 1096 × 662) |
| 제목 `보상` | 440, 210 |
| 기본 보상 줄 | 760, 270 · 400 × 90 (760, 266) |
| 오버킬 보상 줄 | 760, 370 · 400 × 90 (760, 366) |
| 보상 카드 | 300 × 300, 줄 y 520, 간격 60 (518) |
| 아래 버튼 | 760, 870 · 400 × 90. 와이어프레임은 (787, 874 · 346 × 92). 글이 길어져 넓혔다 |

카드 셋이면 450 · 810 · 1170 에 놓인다. 실측은 452 · 812 · 1172 였다.
카드 둘이면 630 · 990 이다. 실측은 632 · 992 였다.

## 박스가 늘어나는 규칙

카드 크기는 늘 300 이다. 개수가 늘면 박스의 가로 폭만 늘어난다.

```
카드 폭 = 개수 × 300 + (개수 - 1) × 60
박스 폭 = 카드 폭 + 40 × 2 를 1100 과 견줘 큰 쪽
```

| 카드 | 카드 폭 | 박스 폭 |
| --- | --- | --- |
| 2 | 660 | 1100 |
| 3 | 1020 | 1100 |
| 4 | 1380 | 1460 |

박스는 넓어져도 화면 가로 가운데를 지킨다.

**유물 4종 와이어프레임의 카드 간격은 40 이었다.**
예시와 코인 2종은 60 이라 60 으로 맞췄다. 40 이 맞으면 설정 에셋에서 바꾼다.

## 모든 보상은 받을 때 한 번에 받는다

2026년 10월 6일에 원재가 정했다. 예전에는 골드를 화면을 여는 순간 먼저 줬다.

기본 보상 골드, 오버킬 골드, 고른 카드를 **아래 버튼을 누르는 순간 함께** 받는다(`RewardScreenController.Received`).
기본 보상 골드에는 방 규칙 골드와 전투에서 얻은 골드가 함께 들어 있다. 전투 골드를 이기는 순간 따로 주지 않는다.
화면을 여는 것만으로는 아무것도 들어오지 않는다. 카드를 건너뛰어도 골드는 받는다.
골드만 있어도 화면을 띄운다. 그때 아래 버튼은 "보상 받기" 다(2026년 10월 6일 원재).

받기 전에 꺼졌다 이어 하면 보상 전부가 그대로 다시 뜬다. 반쯤 받은 상태가 없다.
카드는 하나만 고를 수 있다.

## 카드 고르기

2026년 10월 4일에 원재가 정했다. 기획서 10장의 "카드 입력 시 즉시 획득하고 화면을 종료한다" 를 바꿨다.

| 하는 것 | 결과 |
| --- | --- |
| 고르지 않은 카드를 누른다 | 그 카드로 고른 것이 바뀐다. 밝아지고 붉은 테두리가 생긴다 |
| 이미 고른 카드를 누른다 | 고른 것이 풀린다 |
| 아래 버튼 · 고른 것이 없을 때 | "아이템 선택 건너뛰기". 누르면 카드 없이 받기가 끝난다 |
| 아래 버튼 · 고른 것이 있을 때 | "보상 받기". 누르면 고른 카드를 받고 끝난다 |

카드를 눌러도 화면은 닫히지 않는다. 아래 버튼을 눌러야 닫힌다.
`RewardScreenController.Select` 는 카드를 누른 것, `Confirm` 은 아래 버튼을 누른 것과 같다.
`Choose` 와 `Skip` 은 둘을 이어 부른 것이다. 버튼 글은 `RewardVisualConfig.SkipText`, `ConfirmText` 다.

**받기 전에 받아도 되는지 묻는다**(`RewardScreenController.CanReceive`). false 면 받지 않고 화면을 그대로 둔다.
코인이나 유물이 소지 한도까지 찼을 때 흐름이 버릴 것을 고르게 하는 데 쓴다(2026년 10월 9일 원재).
버리면 흐름이 `Confirm` 을 다시 불러 마저 받고, 포기하면 이 화면에서 다른 카드나 건너뛰기를 고를 수 있다.

## 붙이는 법

### 1. 설정 에셋을 만든다

메뉴 `Slot Hero / 설정 에셋 한 번에 만들기`.
`Assets/SlotHeroConfigs/Reward` 에 자리와 표시 설정이 생긴다.

### 2. 씬을 만든다

메뉴 `Slot Hero / 확인용 씬 만들기 / 보상 화면`.

```
RewardCanvas
  RewardScreen           RewardScreenView + RewardScreenController
    Dim                  Image · 화면을 덮는 막
    RewardBox            Image
    TitleLabel           TMP_Text · "보상"
    BaseGoldRow          Image
      BaseGoldLabel      TMP_Text · "기본 보상"
      BaseGoldIcon       Image · 골드 아이콘
      BaseGoldValue      TMP_Text
    OverkillGoldRow      위와 같은 구성
    CardLayer            빈 RectTransform. 카드가 여기 아래에 만들어진다
    SkipPanel            Image + Button
      SkipLabel          TMP_Text · "아이템 선택 건너뛰기" 또는 "보상 받기"
```

카드 프리팹은 루트에 `RewardCardView`,
자식에 테두리 `Image`, 배경 `Image`, 그림 `Image`, 이름 `TMP_Text`, 태그 `TMP_Text` 를 둔다.
**테두리가 배경보다 앞에 와야 한다.** 고른 카드에서 테두리만 삐져나와 보이게 하려는 것이다.

### 3. 호출

```csharp
// 골드 전부와 고른 카드(없으면 null)가 한 번에 온다. 받은 것을 넣고 한 번에 저장한다.
reward.Received += (gold, card) => { context.GainGold(gold); Give(card); Save(); };
reward.Closed += () => GoToMap();

reward.Open(offer, iconSource);
```

무엇을 담을지는 `Flow` 의 `RewardMaker` 가 정한다.
런 시드와 방 번호로만 정하므로 저장하지 않는다.
같은 방에 다시 들어가면 같은 보상이 나온다.

## 검증 결과

유니티 없이 순수 로직만 따로 빌드해 62건을 확인했고 전부 통과했다.

- 와이어프레임에서 잰 자리와 크기가 맞는다
- 카드 셋이면 450 · 810 · 1170, 둘이면 630 · 990 에 놓인다
- 카드가 넷이 되면 박스가 1460 으로 늘고 카드 크기는 그대로다
- 박스가 넓어져도 가로 가운데를 지킨다
- 골드 줄 둘이 겹치지 않고 건너뛰기가 박스 아래에 있다
- 오버킬 골드가 0 이면 그 줄을 비운다
- 같은 카드가 두 번 나오면 앞뒤가 안 맞는 것으로 본다
- 고른 카드가 더 밝고 글자색이 뒤집힌다
- 문양 카드만 태그 줄을 적는다

게임 씬을 굴려 본 검사에서도 전투 방을 깨면 보상이 뜨고
카드를 고르면 그것만 들어오는 것을 확인했다.

## 기획서에 없어 내가 정한 부분

- **카드 간격 60.** 유물 4종 와이어프레임만 40 이라 다른 둘에 맞췄다
- **박스 안쪽 여백 40.** 카드 셋일 때의 박스 폭에서 거꾸로 낸 값이다
- **카드 안의 그림 190 × 190.** 이름과 태그 줄이 들어갈 자리를 빼고 남은 만큼이다
- **고른 카드 테두리 5.** 와이어프레임에서 잰 값이다

## 이 코드에 없는 것

- **무엇이 얼마나 나오는지.** 보상 기획서가 아직 없다.
  `Flow` 의 `RewardRuleConfig` 에 방마다 골드 범위와 카드 장수를 임시로 두었다
- **아이템 상세 팝업.** `CardHoverChanged` 로 알리기만 한다.
  띄우는 것은 `Popup` 영역의 `ItemDetailView` 가 할 일이다
- **오버킬.** 화면에 적을 자리만 있다. 얼마가 되는지는 전투 시스템이 정한다
