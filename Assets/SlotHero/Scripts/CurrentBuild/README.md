# Slot Hero 현재 빌드 화면 코드

인게임 화면 기획서 v0.2 / 13 현재 빌드 화면 을 옮긴 코드다.
화면 우하단의 현재 빌드 버튼으로 열고, 지금 가진 유물과 코인과 문양,
그리고 태그 9종의 비중을 보여 준다.

무엇을 가지고 있는지 모으는 일은 유물, 코인, 문양 기획서를 따르는 쪽이 맡는다.
이 코드는 받은 내용을 정렬해 그리는 데까지만 한다.

저장소를 받으면 이 `CurrentBuild` 폴더를 통째로 `Assets/Scripts/CurrentBuild`로 옮기면 된다.

## 파일 구성

```
CurrentBuild/
  Runtime/
    Data/
      SymbolTags.cs                  태그 9종을 늘어놓는 도우미와 BuildTagStat.
                                     열거형은 저장소의 SymbolTagType 을 쓴다
      BuildSortOrder.cs              개수 순 · 태그 순 · 이름 순
      CurrentBuildSnapshot.cs        화면에 그릴 것 전부. BuildEntry 와 BuildTagStat 도 여기 있다
      CurrentBuildSort.cs            늘어놓는 차례를 정하는 규칙
      ItemPickRequest.cs             고르기 화면을 열 때 넘기는 것. ItemPickKind 도 여기 있다
    Config/
      CurrentBuildLayoutConfig.cs    화면 자리와 크기. ScriptableObject
      CurrentBuildVisualConfig.cs    색과 글자, 태그 9종의 이름과 색. ScriptableObject
    UI/
      IBuildIconSource.cs            물건 그림을 내주는 창구
      BuildSlotView.cs               물건을 놓는 칸 하나
      BuildTagBarView.cs             태그 한 줄
      CurrentBuildScreenView.cs      화면 배치와 표시
      CurrentBuildScreenController.cs 정렬과 닫기 처리
      ItemPickerScreenView.cs        고르기 화면 표시
      ItemPickerScreenController.cs  고르기 화면의 고르기, 확인, 취소
```

## 기획서 대응표

| 기획서 | 코드 |
| --- | --- |
| 1열 유물 · 슬롯 6개, 획득한 순서대로 왼쪽부터 | `RelicSlotCount`, `GetRelicSlotPosition` |
| 2열 코인 · 최대 5개, 유물보다 10퍼센트 작게 | `CoinSlotCount`, `CoinSlotScale`, `GetCoinSlotSize` |
| 정렬 · 코인 줄 오른쪽 | `SortPosition` |
| 정렬 · 개수 순, 태그 순, 이름 순 | `BuildSortOrder`, `CurrentBuildSort` |
| 3열 이후 문양 · 가로 8칸 | `SymbolColumns`, `GetSymbolSlotPosition` |
| 문양 · 유효 슬롯 최대 36개 | `SymbolSlotLimit` |
| 문양 · 보유한 종류만 슬롯을 표시 | 가진 종류 수만큼만 칸을 만들고 빈 칸을 두지 않는다 |
| 문양 · 종류마다 한 칸에 개수를 함께 표시 | `BuildSlotView` 의 개수 배지 |
| 오른쪽 칸 · 위쪽에 문양 개수 | `CurrentBuildSnapshot.TotalSymbolCount`, `SymbolCountFormat` |
| 오른쪽 칸 · 아래에 태그 9종을 모두 배치 | `SymbolTags.All`, `GetTagStats` |
| 태그마다 고유한 색 | `CurrentBuildVisualConfig.TagVisuals` |
| 보유하지 않은 태그는 막대를 비운다 | `GetTagBarWidth` 가 0을 돌려주고 막대를 끈다 |
| 닫기 · 오른쪽 아래, 열기 전 화면으로 | `ClosePosition`, `Closed` 이벤트 |
| ESC 로도 닫는다 | `CurrentBuildScreenController` 의 닫기 키 |

## 와이어프레임에서 잰 값

기획서가 수치를 적지 않은 자리는 와이어프레임에서 재 왔다.

| 항목 | 자리와 크기 |
| --- | --- |
| 유물 칸 | y 130, 150 × 150, x 60부터 간격 20, 6칸 |
| 코인 칸 | y 340, 135 × 135, x 60부터 간격 20, 5칸 |
| 문양 칸 | y 540, 150 × 160, x 60부터 간격 20, 가로 8칸 |
| 개수 배지 | 62 × 30, 칸 오른쪽 아래에서 8 안쪽 |
| 정렬 | x 1080, y 380, 300 × 60 |
| 오른쪽 칸 | x 1440, y 90, 420 × 830 |
| 태그 막대 | x 1540, 300 × 20, 첫 줄 y 240, 줄 높이 80 |
| 닫기 | x 1440, y 960, 420 × 60 |

자리는 와이어프레임 실측을 10 단위로 옮긴 것이다.
실측은 유물 칸 151 × 151, 문양 칸 151 × 157, 오른쪽 칸 420 × 828, 닫기 y 956 이었다.

코인 칸 135는 유물 칸 150의 90퍼센트다. 기획서의 "10퍼센트 작게"와 맞는다.
**이 비율 때문에 코인 줄만 10 단위로 떨어지지 않는다.** 코인 칸 x 가 60 · 215 · 370 · 525 · 680 이다.
유물 칸을 100 이나 200 으로 바꾸면 코인도 10 단위가 되지만 와이어프레임과 너무 달라져 그대로 두었다.

태그 칸 아래 끝 920과 닫기 위 960 사이가 40으로 떨어지고, 닫기 아래로 60이 남는다.
태그 기호 x 1460은 태그 칸 왼쪽 1440에서 안쪽 여백 20만큼 들어온 자리다.

### 문양 줄과 스크롤

문양은 가진 종류 수만큼만 칸을 만든다. 4종이면 한 줄, 9종이면 두 줄이 되고 빈 칸은 두지 않는다.
유효 슬롯 36개를 넘겨 받으면 뒤쪽은 그리지 않고 경고를 남긴다.

와이어프레임의 칸 크기로는 한 화면에 세 줄, 스물네 칸까지 들어간다.
그보다 많으면 왼쪽 줄들이 세로로 스크롤된다.
오른쪽 태그 칸과 닫기는 스크롤 창 밖에 있어 늘 보인다.

스크롤 창은 세로로 화면 전체, 가로로 오른쪽 칸 앞까지다.
창을 화면 왼쪽 위에 맞춰 두므로 칸 자리는 기획서 좌표를 그대로 쓴다.

마지막 줄이 화면 안에 다 보이는데 아래 여백 때문에만 넘치는 경우에는
여백을 버리고 화면 높이에 맞춘다. 볼 것이 없는데 스크롤이 생기지 않게 하기 위해서다.
세 줄까지는 스크롤이 움직이지 않고 네 줄부터 움직인다.

**휠 한 칸에 60 픽셀씩 움직인다.** 2026년 10월 5일까지 스크롤의 휠 거리가 유니티 기본값 1 이었는데
그때 좌표 배율이 12 라 한 칸에 1/12 픽셀만 움직여 원재가 네 줄부터 아래를 볼 수 없다고 짚었다.
지금 배율 1 에서도 기본값 1 은 한 칸에 1 픽셀이라 휠 거리를 꼭 넣는다.
스크롤은 모두 `UiSceneBuilder.AddScroll` 로 만들어 휠 거리를 함께 넣는다.
칸 사이 빈 곳에서도 휠이 먹도록 스크롤 창에 투명한 바탕을 깔았고, 줄 이름도 스크롤 안에 넣어 칸과 함께 움직인다.

## 고르기 화면

이벤트와 성소에서 가진 것이나 목록에서 하나를 직접 고를 때 이 화면과 비슷한 화면을 띄운다.
2026년 10월 5일 원재가 정했다. 지금 여는 곳은 성소의 문양 변경과 08 피의 거래 다.

- 유물을 고르면 유물만, 코인을 고르면 코인만, 문양을 고르면 정렬 칸과 오른쪽 태그 비중까지 나온다
- 칸 크기와 오른쪽 칸 자리는 이 화면 설정을 그대로 쓴다. 칸은 제목 아래에서 가로 여덟 칸씩 늘어서고 많으면 스크롤한다
- 칸을 누르면 금빛 테두리로 골라지고, 다시 누르면 풀리고, 다른 칸을 누르면 바뀐다. 보상 화면의 카드 고르기와 같다
- 아래 줄에 고른 것과 그 결과(`[해일] 을 무작위 문양으로 바꾼다`)를 적고 확인 버튼으로 정한다. 고른 것이 없으면 확인이 흐리고 눌리지 않는다
- 취소나 ESC 면 고르지 않고 닫는다. 취소 버튼 글은 요청이 바꿀 수 있다(`CancelText`)
- 반드시 골라야 하는 요청(`Cancellable` 을 끈 것)은 취소 버튼을 감추고 ESC 도 받지 않는다
- 고르는 칸에도 아이템 상세 오버레이가 뜬다

2026년 10월 9일부터 코인과 유물의 소지 한도가 찼을 때 **버릴 것 고르기**에도 쓴다. 취소 버튼은 "포기" 다.
한도가 줄어 넘쳐 버릴 때는 반드시 골라야 하는 요청이라 포기가 없다.

현재 빌드 화면의 유물 칸과 코인 칸 수도 그날부터 런의 소지 한도(`CurrentBuildSnapshot.RelicCapacity`, `CoinCapacity`)를 따른다.
한도가 없으면 설정의 6 칸과 5 칸이다. 한도가 줄어 잠시 넘친 동안에는 가진 수만큼 놓아 가려지지 않게 한다.

"보유 중 무작위 3개" 처럼 칸이 정해진 이벤트 선택지는 이 화면을 쓰지 않고 지금처럼 선택지 셋으로 둔다. 원재가 정했다.

| 항목 | 자리와 크기 |
| --- | --- |
| 제목 | x 60, y 90 |
| 정렬 (문양만) | x 1080, y 80, 300 × 60 |
| 아래 줄 | x 60, y 960, 1320 × 60 |
| 확인 | x 1440, y 960, 200 × 60 |

### 태그 막대의 길이

막대는 그 태그를 가진 문양이 전체 문양 중 얼마인지로 정해진다.
화면 예시는 문양 18장에 토성 6장이고 막대가 300 중 100이다. 6 나누기 18이 3분의 1이다.
가진 문양이 하나도 없으면 모든 막대가 비워진다.

### 태그 색

여덟 가지는 화면 예시에서 뽑았다. 해왕성은 예시에 0장이라 막대가 비어 있어 내가 정했다.

## 붙이는 법

### 1. 설정 에셋을 만든다

프로젝트 창에서 우클릭 후 `Create > Slot Hero > 현재 빌드`에서 두 개를 만든다.

- 현재 빌드 화면 자리 설정 (`CurrentBuildLayoutConfig`)
- 현재 빌드 화면 표시 설정 (`CurrentBuildVisualConfig`)

### 2. 씬을 만든다

```
CurrentBuildScreen         CurrentBuildScreenController, 화면 루트
  Dim                      Image · 화면을 덮는 어두운 막
  Scroll                   ScrollRect · 세로만 켠다
    Viewport               Mask 또는 RectMask2D
      Content              여기 아래는 기획서 좌표를 그대로 쓴다
        RelicLabel         TMP_Text
        RelicLayer         빈 RectTransform. 유물 칸이 여기 아래에 만들어진다
        CoinLabel          TMP_Text
        CoinLayer          빈 RectTransform
        SymbolLabel        TMP_Text
        SymbolLayer        빈 RectTransform
  SortPanel                Image + Button
    SortLabel              TMP_Text · "정렬". 칸을 가득 채우고 왼쪽에 붙인다
    SortValueLabel         TMP_Text · "개수 순". 칸을 가득 채우고 오른쪽에 붙인다
  TagPanel                 Image
    SymbolCountLabel       TMP_Text · "문양 18장"
    TagTitleLabel          TMP_Text · "태그 비중"
    TagLayer               빈 RectTransform. 태그 줄이 여기 아래에 만들어진다
  ClosePanel               Image + Button
    CloseLabel             TMP_Text · "닫기"
    CloseShortcutLabel     TMP_Text · "Tab / ESC"
```

칸 프리팹은 루트에 `BuildSlotView` + 배경 `Image`,
자식에 물건 그림 `Image` 와 개수 배지(`Image` + `TMP_Text`)를 둔다.
유물과 코인 칸은 배지를 감추고 문양 칸만 보여 준다.

**정렬 버튼의 글자 둘은 반드시 칸을 가득 채워 좌우로 갈라 붙인다.**
안 그러면 둘 다 칸 한가운데에 놓여 `정렬` 위에 `개수 순` 이 올라탄다.

**줄 이름과 칸 제목은 `LabelSize` 로 크기를 잡는다.**
`ApplyLayout` 의 `PlaceLabel` 이 자리와 함께 크기도 준다.
크기를 안 잡으면 유니티가 넣어 주는 100 × 100 이 남아
가운데 맞춤인 글자가 칸 절반만큼 아래로 밀려 문양 칸 뒤로 들어가고,
긴 이름은 폭이 모자라 한 자씩 줄바꿈된다.

칸 제목 둘 사이의 세로 간격은 `PanelTitleGap` 이다.
코드에 숫자로 박아 두면 좌표 배율을 타지 못해 화면에서 둘이 겹친다. 실제로 한 번 그랬다.

태그 줄 프리팹은 루트에 `BuildTagBarView`,
자식에 기호 `Image` 와 기호 `TMP_Text`, 이름 `TMP_Text`, 장수 `TMP_Text`,
막대 바닥 `Image` 를 두고 **채워지는 막대 `Image` 는 막대 바닥의 자식**으로 넣는다.
`Bind` 가 채워지는 막대의 자리를 0 으로 놓기 때문에 바깥에 두면 줄 왼쪽 끝에서 시작해 버린다.

`Bind` 는 막대 길이와 색과 글자만 정한다. 자리는 전부 프리팹에서 잡아야 한다.
줄의 왼쪽 위가 `TagSymbolX` 이고 높이가 `TagRowHeight` 라
왼쪽 가운데 기준점은 막대 위쪽 끝에서 20 위에 있다. 그래서 줄 안의 자리는 이렇다.

| 무엇 | x | y | 크기 |
| --- | --- | --- | --- |
| 행성 기호 | 0 | -10 | 60 × 60 |
| 이름 | 80 | 0 | 150 × 30 |
| 장수 | 230 | 0 | 150 × 30 |
| 막대 바닥 | 80 | -30 | 300 × 20 |

x 80 은 `TagBarX` 1540 에서 `TagSymbolX` 1460 을 뺀 값이다.

정렬 칸과 오른쪽 태그 칸, 닫기는 스크롤 밖에 둔다. 스크롤해도 자리를 지켜야 하기 때문이다.
`ScrollRect` 의 Content 와 Viewport 는 코드가 크기를 잡으므로 자리를 미리 맞출 필요가 없다.

자리는 `CurrentBuildScreenView` 를 우클릭해 `기획서 자리로 맞추기` 를 누르면 잡힌다.

### 3. 호출

```csharp
// 현재 빌드 버튼을 눌렀을 때. 내용은 아이템 쪽이 모아 넘긴다
hud.CurrentBuildRequested += () =>
{
    CurrentBuildSnapshot snapshot = inventory.BuildSnapshot();
    buildScreen.Open(snapshot, iconSource);
    hud.SetCurrentBuildOpen(true);
};

// 닫으면 버튼을 되살린다
buildScreen.Closed += () => hud.SetCurrentBuildOpen(false);
```

`CurrentBuildSnapshot` 을 채우는 것이 아이템 쪽이 할 일이다.
유물과 코인은 `BuildEntry.Item`, 문양은 개수와 **서로 다른 태그 둘**을 함께 담는
`BuildEntry.Symbol(id, 이름, 개수, 첫태그, 둘째태그)` 를 쓴다.

태그 장수는 따로 넣지 않는다. `GetTagStats()` 가 문양에서 매번 세어 아홉 줄을 돌려준다.
문양 한 장이 태그 둘에 들어가므로 태그 장수의 합은 문양 장수의 두 배다.

## 검증 결과

유니티 없이 순수 로직만 따로 빌드해 95건을 확인했고 전부 통과했다.

- 유물 6칸, 코인 5칸, 문양 가로 8칸이 제자리에 놓인다
  (유물 x 60 · 230 · 910, 코인 x 60 · 215 · 680, 문양 x 60 · 570)
- 코인 칸이 유물 칸의 90퍼센트인 135다
- 아홉 번째 문양이 둘째 줄 첫 칸으로 내려간다
- 가진 종류만큼만 줄이 생긴다. 4종이면 한 줄, 9종이면 두 줄, 36종이면 다섯 줄이고
  유효 슬롯을 넘겨 받아도 다섯 줄에서 멈춘다
- 세 줄까지는 스크롤이 움직이지 않고 네 줄부터 움직이며,
  내용 높이가 마지막 줄 아래 여백까지 담는다
- 태그 막대가 화면 예시와 같은 길이로 나온다
  (문양 18장에 6장이면 100, 5장이면 83, 4장이면 67, 3장이면 50, 0장이면 0)
- 통계가 늘 아홉 줄이고 태양계 차례로 나온다
- 문양 한 장이 태그 둘에 들어간다. 24장이면 태그 합이 48이다
- 개수 순, 태그 순, 이름 순이 모두 제대로 서고 값이 같으면 이름으로 마저 가른다
- 태그 순은 첫 태그로 가르고 첫 태그가 같으면 둘째 태그로 마저 가른다
- 태그 여덟 가지 색이 화면 예시에서 뽑은 값과 같고 아홉 가지가 서로 다르다
- 정렬 칸이 코인 줄 오른쪽에 있고 문양 여덟 칸이 오른쪽 칸을 넘지 않는다

## 기획서와 와이어프레임이 어긋나는 곳

**기획서 목차와 와이어프레임 번호가 다르다.**
문서 목차와 슬라이드 제목은 "13 현재 빌드 화면"인데
와이어프레임 프레임 이름과 내보낸 이미지 파일은 "14 현재 빌드 화면"이다.

## 기획서에 없어 내가 정한 부분

확인이 필요하면 알려 주면 고친다.

1. **정렬이 무엇을 늘어놓는지** 기획서는 정렬 칸의 자리와 기준만 적었다.
   문양과 태그 통계를 같은 기준으로 함께 늘어놓게 했다.
   개수 순은 문양과 태그 둘 다에 뜻이 있고, 화면 예시도 둘 다 개수 순으로 서 있다.
2. **값이 같을 때의 차례** 개수가 같으면 이름으로 마저 가른다.
   그래야 같은 빌드를 다시 열어도 늘 같은 자리에 놓인다.
3. **태그 순의 차례** 태양계 순서로 두었다. 수성부터 명왕성까지다.
4. **정렬 칸을 누르면** 개수 순 → 태그 순 → 이름 순으로 돌아간다.
5. **해왕성 막대 색** 예시에 0장이라 색을 알 수 없어 `#3A5FA8` 로 정했다.
6. **닫기 단축키** 기획서는 ESC 만 적었고 와이어프레임은 "Tab / ESC" 로 적혀 있다.
   둘 다 받게 했다.
7. **태그 기호** 와이어프레임의 행성 기호를 글자로 넣었다.
   그림으로 바꾸려면 기호 자리를 `Image` 로 바꾸면 된다.
8. **스크롤이 도는 범위** 물어서 문양이 많을 때 스크롤로 보기로 정했다.
   왼쪽 줄들만 스크롤하고 오른쪽 태그 칸과 닫기는 자리를 지킨다.
   내용이 화면 안에 다 보이는데 아래 여백 때문에만 넘치는 경우에는 여백을 버려
   볼 것이 없는데 스크롤이 생기지 않게 했다.
