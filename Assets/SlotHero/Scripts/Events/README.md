# Slot Hero 이벤트 화면 코드

인게임 화면 기획서 v0.2 / 11 이벤트 화면 을 옮긴 코드다.

이벤트 기획서는 아직 없다. 어떤 이벤트가 나오고 무엇을 주는지는 그 문서 소관이라
여기서는 화면 기획서가 정한 것까지만 만들었다.
즉 삽화와 본문과 선택지를 그리고, 무엇을 골랐는지 알리고,
고른 뒤의 화면 규칙을 지키는 데까지다.

저장소를 받으면 이 `Events` 폴더를 통째로 `Assets/Scripts/Events`로 옮기면 된다.
네임스페이스를 `SlotHero.Event` 가 아니라 `SlotHero.Events` 로 둔 것은
`event` 가 C# 예약어라 네임스페이스 이름으로 쓸 수 없기 때문이다.

## 파일 구성

```
Events/
  Runtime/
    Data/
      EventEffectKind.cs      획득 · 소모 · 부족
      EventEffectLine.cs      선택지 칸에 적을 한 줄
      EventChoice.cs          선택지 하나와 그 상태
      EventChoiceText.cs      선택지 칸에 적을 글을 만드는 규칙
      EventPage.cs            한 화면분과 선택 후 갱신 규칙. EventResult 도 여기 있다
      EventProgress.cs        이벤트 한 번의 진행 기록
    Config/
      EventLayoutConfig.cs    화면 자리와 크기. ScriptableObject
      EventVisualConfig.cs    색과 글자. ScriptableObject
      EventIllustrationConfig.cs  삽화 목록. 식별자와 그림. ScriptableObject
    UI/
      IEventIllustrationSource.cs  삽화를 내주는 창구
      EventChoiceView.cs      선택지 칸 하나
      EventScreenView.cs      화면 배치와 표시
      EventScreenController.cs 진행 처리
  Art/                        삽화. 파일 이름이 삽화 식별자다. 남은 그림 폴더는 가져오지 않는다
```

## 와이어프레임에서 잰 값

기획서가 수치를 적은 것은 삽화 1200 × 500 뿐이라 나머지는 와이어프레임에서 재 왔다.

| 항목 | 자리와 크기 |
| --- | --- |
| 삽화 | x 360, y 100, 1200 × 500 |
| 본문 칸 | x 360, y 640, 580 × 350 (실측 348) |
| 본문 글자 | 칸 안쪽으로 좌우 30, 위 40 |
| 선택지 칸 | x 980, y 640, 580 × 40 (실측 36), 칸 사이 10, 최대 7칸. 글이 길면 세로로만 늘어난다 |
| 선택지 글자 | 칸 안쪽으로 좌우 20, 위아래 10 |

선택지 일곱 칸이 차지하는 높이는 40 × 7 + 10 × 6 = 340 이고
그 아래 칸 하나가 더 들어가려면 390 이 필요해 본문 칸 높이 350 을 넘는다.
그래서 최대 칸 수를 일곱으로 뒀다. 실측값 36 과 348 로 세어도 일곱이라 수가 달라지지 않는다.

본문 오른쪽 끝이 940, 선택지 왼쪽 끝이 980이라 화면 가운데 960 에서 20씩 떨어져 있고,
본문 왼쪽 끝 360 과 선택지 오른쪽 끝 1560 도 가운데에서 600씩 떨어져 좌우가 대칭이다.

색은 다음과 같다.

| 자리 | 색 |
| --- | --- |
| 본문 칸과 선택지 칸 | `#D9D9D9` |
| 이미 고른 선택지 칸 | `#767574` |
| 얻는 것 | `#1E8A3C` |
| 필요한 것을 갖췄을 때 | `#1E8A3C` |
| 필요한 것을 갖추지 못했을 때 | `#C0392B` |
| 글자 | `#1F1B16` |

조건을 채우지 못한 칸은 칸 색을 바꾸지 않는다.
기획서가 "부족한 항목을 빨간색으로 표시하고 선택할 수 없게 한다"까지만 정했고
와이어프레임에서도 칸 색이 그대로이기 때문이다.

글자 크기는 인게임 화면 기획서 04 화면 공통 규칙 의 텍스트 표를 따라
본문 24픽셀, 선택지 26픽셀 굵게로 뒀다.
와이어프레임은 이보다 작게 그려져 있어 실제 폰트를 넣은 뒤 다시 볼 필요가 있다.

## 선택지 칸에 적히는 글

색을 글자 안에 태그로 넣으므로 칸마다 글자 하나면 된다.

| 선택지 | 나오는 글 |
| --- | --- |
| 결과가 공개된 것 | `산책할까?  —  체력 5 증가` (뒤쪽이 초록) |
| 필요한 것을 갖춘 것 | `간식 먹을래? [간식]  —  유물 획득` (대괄호가 초록) |
| 필요한 것을 갖추지 못한 것 | `간식 먹을래? [간식]  —  유물 획득` (대괄호가 빨강, 누를 수 없음) |
| 결과를 알 수 없는 것 | `쫓아가기  —  ?` |

### 필요한 항목

그 선택지를 고르는 데 필요한 것은 갖췄든 아니든 늘 선택지 문구 바로 뒤에 괄호로 적는다.
갖췄으면 초록색, 갖추지 못했으면 빨간색이고, 하나라도 갖추지 못하면 그 선택지를 누를 수 없다.
무엇이 있어야 하는지를 먼저 보여 주고 상태는 색으로 알리는 방식이다.

필요한 것이 둘 이상이면 각각 괄호로 감싼다. 항목마다 색이 다를 수 있기 때문이다.
`열어 본다 [열쇠] [등불]  —  유물 획득` 에서 열쇠는 초록, 등불은 빨강이 될 수 있다.

괄호 안에 무엇을 적을지는 이벤트 쪽이 정한다.
항목 이름만 넘기면 `[간식]` 이 되고, `간식 미보유` 처럼 상태까지 넘기면 그대로 적힌다.

구분자와 괄호 꼴, 색은 `EventVisualConfig` 에서 바꾼다.

## 붙이는 법

### 1. 설정 에셋을 만든다

프로젝트 창에서 우클릭 후 `Create > Slot Hero > 이벤트`에서 두 개를 만든다.

- 이벤트 화면 자리 설정 (`EventLayoutConfig`)
- 이벤트 화면 표시 설정 (`EventVisualConfig`)

### 2. 씬을 만든다

```
EventScreen                EventScreenController, 화면 루트
  Illustration             Image
  BodyPanel                Image
    BodyLabel              TMP_Text
  ChoiceLayer              빈 RectTransform. 선택지 칸이 여기 아래에 만들어진다
```

선택지 칸 프리팹은 루트에 `EventChoiceView` + `Button` + 배경 `Image`,
자식에 `TMP_Text` 하나를 둔다. 그 프리팹을 `EventScreenView` 에 물린다.

## 선택지 칸은 글에 맞춰 늘어난다

와이어프레임의 칸 높이 40 은 한 줄짜리 선택지를 그린 것이다.
`값을 치른다 [골드 20]  —  골드 20 소모, 코인 획득` 처럼 긴 선택지는 한 줄에 안 들어간다.

**가로는 그대로 두고 세로로만 늘린다.**
기획서 11장이 본문과 선택지를 화면 가운데 기준 좌우 대칭으로 정했으므로 폭은 건드리면 안 된다.

- `EventChoiceView.Bind` 가 글을 넣으면서 TMP 에 이 폭에서 몇 줄이 되는지 묻는다
- `EventLayoutConfig.GetChoiceHeight` 가 글 높이에 위아래 여백을 더해 칸 높이를 낸다.
  한 줄이면 40 그대로다
- `EventScreenView.PlaceChoices` 가 앞 칸이 실제로 차지한 높이를 더해 가며 아래로 내려간다.
  두 줄짜리가 끼면 그 뒤 칸이 그만큼 더 내려간다
- 쌓인 높이가 본문 칸 높이 350 을 넘으면 경고를 남긴다

**글자 줄바꿈을 켜 두어야 한다.** 끄면 칸이 늘어나도 글이 한 줄로 이어져 오른쪽으로 삐져나간다.

선택지 수는 이벤트마다 다르고 고를수록 늘어나므로 칸은 코드가 복제해 만든다.
자리는 `EventScreenView` 를 우클릭해 `기획서 자리로 맞추기` 를 누르면 잡힌다.

### 3. 호출

```csharp
// 이벤트 방에 들어갈 때. 페이지는 이벤트 기획서를 따르는 쪽이 만들어 넘긴다
EventPage page = new EventPage();
page.IllustrationId = "dog";
page.BodyText = "길이 좁아지는 곳에 개 한 마리가 앞을 막고 있다. ...";
page.Choices.Add(EventChoice.Known("walk", "산책할까?", EventEffectLine.Gain("체력 5 증가")));
page.Choices.Add(EventChoice.Known(
    "snack", "간식 먹을래?",
    EventEffectLine.Requirement("간식", inventory.Has("snack")),
    EventEffectLine.Gain("유물 획득")));
page.Choices.Add(EventChoice.Hidden("follow", "쫓아가기"));

eventScreen.Open("event_dog", page, illustrations);

// 선택지를 골랐을 때. 결과를 정해 되돌려 준다
eventScreen.ChoiceSelected += (eventId, choiceId) =>
{
    EventResult result = eventTable.Resolve(eventId, choiceId);
    eventScreen.ApplyResult(result);
};

// 이어지는 선택지가 없어 이벤트가 끝났을 때
eventScreen.Finished += eventId =>
{
    eventScreen.Close();
    rewardScreen.Open();
};
```

조건을 채웠는지 따지는 일은 이 코드가 하지 않는다.
골드가 있는지 물건이 있는지를 판정한 결과를
`EventEffectLine.Requirement` 의 두 번째 값으로 넘겨 주면
화면이 초록이나 빨강으로 적고, 갖추지 못한 것이 있으면 누를 수 없게 한다.

## 설정 에셋의 자료를 직접 고치지 않는다

`EventScreenController.Open` 과 `ApplyResult` 는 받은 것을 **복사해 쓴다.**

이벤트 목록 설정이 들고 있는 쪽을 그대로 받아 쓰던 때가 있었다.
`EventPage.ApplyResult` 가 본문과 선택지 목록을 제자리에서 갈아 끼우므로
설정 에셋이 그 자리에서 영구히 바뀌었다.
그래서 **같은 이벤트 방에 다시 들어가면 앞의 진행이 그대로 이어져** 열렸다.

복사를 넘겨주는 쪽에 맡기지 않고 받는 쪽에서 한다. 한 군데만 보면 되게 하려는 것이다.
`EventPage.Clone`, `EventResult.Clone`, `EventChoice.Clone` 이 그 일을 한다.

## 각본은 화면 여럿을 오가는 꼴이다

`이벤트 기획서 초안` 을 받아 2026년 10월 2일에 구조를 바꿨다.

11 이벤트 화면 만 보고 만들었을 때는 **쪽 하나가 자라는 꼴**이었다.
고른 선택지가 위에 남고 새 선택지가 아래에 쌓이는 그 화면 그대로다.
그런데 이벤트 기획서는 **화면 여럿을 오가는 꼴**이다.
확률로 갈리고, 앞 화면으로 되돌아가고, 전투를 거쳤다가 돌아온다.

**그리는 쪽은 그대로 두고 화면 그래프를 위에 얹었다.**
11장의 쌓이는 표시가 화면이 바뀌는 모습으로도 그대로 읽히기 때문이다.
`EventRunner` 가 그 사이를 옮긴다. 화면 하나가 곧 `EventResult` 하나다.

| 기획서 | 코드 |
| --- | --- |
| 이벤트는 여러 화면으로 이루어진다 | `EventScript.Screens` |
| 화면은 일러스트 1개, 스토리, 선택지 1~5개 | `EventScreen` |
| 선택지 종류 · 진행 · 실행 · 종료 | `EventChoiceKind` |
| 작업 · 획득 · 지불 · 손실 · 교환 · 변경 · 전투 시작 | `EventActionKind` |
| 50퍼센트 확률로 화면 3A로 넘어간다 | `EventScreenChoice.Branches` |
| 보유 문양 중 무작위 3종 | `EventChoiceFill`, `IEventWorld.Collect` |
| 조건을 못 채운 선택지는 비활성에 부족한 조건 표시 | `IEventWorld.CanDo` 가 까닭을 글로 돌려준다 |
| 종료 선택지는 항상 비용 없이 고를 수 있다 | `MakeChoice` 가 종료는 조건을 안 본다 |
| 전투가 끝나면 마무리 화면으로 넘어간다 | `EventRunner.ResumeAfterCombat` |
| 전투 골드 보상이 2배가 된다 | `EventAction.DoubleCombatReward` |

### 끊기면 런이 막힌다

각본이 없는 화면을 가리키거나, 고를 수 있는 선택지가 하나도 없는 화면이 나오면
그 자리에서 방을 나갈 수가 없다.

세 겹으로 막아 뒀다.

1. `EventScript.FindBrokenLinks` 가 없는 화면과 아무 데서도 못 가는 화면을 찾는다
2. `EventRunner.EnsureWayOut` 이 고를 것이 없는 화면에 떠나기를 끼워 넣는다.
   채울 대상이 하나도 없어 선택지가 통째로 사라질 수 있기 때문이다
3. `GameFlowController` 가 갈 화면이 없으면 이벤트를 끝낸 것으로 넘긴다

검사가 각본을 **시드 마흔 개로 모든 길을 밟아** 전부 끝나는지 본다.

### 앞 화면의 선택을 기억한다

02 힘을 새기는 것 은 화면 2 에서 고른 태그를 화면 3 에서 쓰고,
04 닮은 모습 은 화면 1 의 문양과 화면 2 의 태그를 화면 3 에서 쓴다.
그래서 러너가 앞 화면의 선택을 기억한다.

| 자리 | 하는 일 |
| --- | --- |
| `EventScreenChoice.RememberAs` | 고르면 지목된 대상을 이 이름으로 기억한다 |
| `EventScreenChoice.FillSourceKey` | 기억해 둔 문양의 태그로 선택지를 채운다 |
| `EventScreenChoice.FillExcludeKeys` | 기억해 둔 것을 후보에서 뺀다. 문양이면 그 태그 둘을 뺀다 |
| `EventAction.RecallKeys` | 기억해 둔 것을 작업에 넘긴다. `EventTarget.Recalled` 로 받는다 |

기억은 이벤트 하나 안에서만 산다. 이벤트 방에 들어갈 때마다 러너를 새로 만든다.

태그는 식별자로 `SymbolTagType` 의 영어 이름을 쓰고, 화면에는 현재 빌드 화면과 같은 한국어 이름이 나온다.
태그를 다루는 작업이 셋 생겼다. `GainSymbolByTags`, `ReshapeSymbol`, `PurgeTag` 다.

`EventScripts.BuildAll` 이 짓는다. 번호는 기획서 5장 이벤트 목록 의 번호다.

### 등장 스테이지와 출현 비중

이벤트마다 `MinStage`, `MaxStage`, `Weight` 칸이 있다. 2026년 10월 9일 외부 검토가 권해 칸만 만들었다. 수치는 기획서가 오면 에디터에서 넣는다.

- `Weight` 는 나올 수 있는 이벤트끼리의 비중이다. 0 이하는 1 로 본다. 이벤트를 빼려면 스테이지 범위를 좁힌다

### 물건은 "종류 — [이름]" 으로 적는다

2026년 10월 5일에 원재가 "곡괭이 — 유물 1개" 가 아니라 "유물 — [곡괭이]" 로 적으라고 했다. 문양과 코인도 같다.

- 받는 물건은 선택지 이름에 종류(`유물`, `문양`, `코인`)를, 얻는 줄에 초록 `[이름]` 을 적는다
- 가진 것 중에서 내주는 것은 선택지 이름이 `문양 선택`, `코인 선택` 이고 잃는 줄에 빨간 `[이름]` 을 적는다
- "고른 코인 1개", "유물 1개" 같은 말은 쓰지 않는다. 지목된 이름이 없는 것은 `무작위 유물` 처럼 적는다
- 01 수상한 기운 은 선택지 이름이 PDF 의 통로 이름이고 받을 문양을 얻는 줄에 `[이름]` 으로 적는다

각본에는 이름 자리 `{name}` 을 적고(`EventScripts.Named`) 실행기가 지목한 물건 이름으로 바꾼다.
각본 검사가 이 꼴을 지키는지 본다.

### 코인 등급은 가장 낮은 등급과 가장 높은 등급을 넘지 않는다

25 미치광이 대장장이 는 코인을 한 등급 내리고 27 축복 은 한 등급 올린다.
**가장 낮은 코인을 내리거나 가장 높은 코인을 올리면 같은 등급에서 뽑는다.** 2026년 10월 8일 원재가 정했다.

예전에는 옮긴 등급에 코인이 없으면 아무 코인이나 뽑았다. 그래서 전설 코인이 축복을 받고 일반 코인이 될 수 있었다.

- 가장 낮고 높은 등급은 목록에 실제로 있는 코인으로 정한다
- 옮긴 등급이 비어 있으면 원래 등급 쪽으로 한 칸씩 물러난다.
  올리기가 원래보다 낮은 코인을, 내리기가 원래보다 높은 코인을 주는 일이 없다
- 규칙은 `RunEventWorld.PickCoinStepped` 하나에 있다

### 다른 선택지가 모두 막히면 체력 손실 선택지를 연다

4장 공통 규칙 이 "부정 이벤트와 무작위 이벤트에서 체력 손실로 현재 체력이 1 미만이 되는 선택지는 비활성으로 표시한다.
다른 선택지가 모두 비활성이면 그 선택지를 활성으로 표시한다" 고 정했다. 2장 도 부정 이벤트의 "손해는 피할 수 없다" 고 정했다.

예전에는 고를 것이 없으면 바로 공짜 "떠난다" 를 끼웠다. 그래서 체력 10 · 골드 0 으로 09 부식 을 만나면 아무것도 잃지 않고 끝났다.
2026년 10월 8일 외부 검토가 짚어 고쳤다.

- `EventRunner.EnsureWayOut` 이 체력이 모자라서만 막힌 강제 손실 선택지를 먼저 다시 연다
- 대상은 부정 · 무작위 이벤트의 체력 손실뿐이다. 최대 체력 손실은 지금 체력을 1 아래로 떨어뜨리지 않아 이 규칙에 들지 않는다. 긍정 이벤트(29 생명력 거래)에서 스스로 체력을 내주는 선택지는 막힌 채로 둔다
- 그래도 고를 것이 없을 때만 떠나는 선택지를 끼운다
- 강제 손실로 체력이 0 이 되면 흐름이 런을 끝낸다

### 문양 덱은 릴 수보다 작아지지 않는다

전투 시스템 기획서 04 가 "문양 풀이 슬롯 릴 갯수보다 적은 경우는 존재하지 않는다" 고 정했다. 릴은 5 ~ 7개다.
지금 덱을 줄이는 길은 10 정신 붕괴 의 문양 손실 하나뿐이다. 시작 덱이 서른여섯 장이라 한 런에서는 닿기 어렵지만
엔드리스 모드처럼 런이 길어지면 거듭 만나 줄 수 있다. 2026년 10월 8일 외부 검토가 짚었다.

`RunCatalogConfig.MinimumDeckSize`(기본 6) 아래로는 문양을 잃지 못한다. 2026년 10월 9일 원재가 6 으로 정했다.
잃는 선택지는 `문양 6장 유지` 를 적고 막히며, 다른 선택지가 없으면 떠나는 선택지가 생긴다.
릴 수가 하나로 정해지면 그 값으로 맞춘다.

### 코인과 유물의 소지 한도

받을 코인이나 유물이 소지 한도를 넘는 선택지는 막지 않는다. 고르면 흐름이 먼저 버릴 것을 고르게 한다(`Flow/README.md` 의 소지 한도).
각본을 굴리는 쪽은 `IEventWorld.NeedsRoom` 으로 그런 선택지를 가려 두고(`EventRunner.NeedsRoom`),
화면에서 고를 수 있는 것이 그런 선택지뿐이면 떠나는 선택지를 끼운다. 버리지 않고 포기했을 때 나갈 길이다.
몇 개를 버려야 하는지는 `RunEventWorld.RoomShortfall` 이 센다. 코인 받기는 하나, 유물 받기는 `Count` 개다.

한도를 바꾸는 작업 `ChangeCoinCapacity` · `ChangeRelicCapacity` 도 두었다. `Amount` 만큼 바꾸고 음수면 줄인다.
어느 이벤트가 쓰는지는 아직 정해지지 않았다. 2026년 10월 9일 원재가 정했다.

### 도전 이벤트의 부정 효과

3장 도전 이벤트 공통 규칙 의 부정 효과 목록(D1 ~ D6)을 `EventCombatPenalty.SpecDefaults` 에 옮겼다.
목록 에셋은 `RunEventConfig.CombatPenalties` 다.

## 기획서에 없어 정한 부분

아래는 모두 물어서 정한 것이다.

1. **고른 선택지가 쌓이는 방식** 기획서는 "선택한 선택지를 맨 위로 올린다"까지만 적었다.
   여러 번 고르는 이벤트에서는 고른 것들이 고른 차례대로 위에 쌓이고
   새 선택지가 그 아래에 붙는다.
   와이어프레임의 "고른 선택지 · 흐리게 남긴다", "다음 선택지 · 아래로 쌓인다"를 따른 것이다.
2. **이미 고른 선택지의 표시** 칸을 어두운 회색으로 바꾸고 투명도를 낮춰 흐리게 남긴다.
3. **필요한 항목의 표시** 그 선택지를 고르는 데 필요한 것을
   갖췄든 아니든 선택지 문구 바로 뒤에 괄호로 적고,
   갖췄으면 초록색, 갖추지 못했으면 빨간색으로 보여 준다.
   둘 이상이면 항목마다 색이 다를 수 있어 각각 괄호로 감싼다.
4. **한 선택지가 여러 가지를 줄 때** 기획서 예시는 항목이 하나뿐이라 둘 이상일 때가 없다.
   칸 높이가 40이라 한 줄만 들어가므로 줄을 바꾸지 않고 쉼표로 잇는다.
   `거래한다  —  골드 20 소모, 문양 획득` 처럼 나온다.
5. **선택지 칸 수** 한 화면에 일곱 칸까지 둔다. 본문 칸 높이 350 안에 들어가는 수와 같다.
   고른 이력과 새 선택지가 함께 놓인다. 일곱을 넘으면 **고른 이력만** 가장 오래 전 것부터 지우고 새 선택지는 지우지 않는다.
   지난 이력보다 지금 고를 수 있는 선택지가 보이는 쪽이 중요하기 때문이다. `EventLayoutConfig.MaxChoiceCount` 에서 바꾼다.
   예전에는 이력과 새 선택지를 한 줄로 세워 앞에서부터 잘라, 새 선택지가 많으면 유일한 떠난다 까지 사라질 수 있었다.
   2026년 10월 9일 외부 검토가 짚었고 원재가 "이력만 줄인다" 로 정했다.
6. **각본 화면 하나의 선택지 수는 5개까지다.** 2026년 10월 9일 원재가 정했다. 이벤트 기획서 초안 1장 의 "선택지 1~5개" 다.
   인게임 화면 기획서와 이벤트 기획서 PDF 는 개수를 정하지 않았다. `RunEventConfig.MaxChoicesPerScreen` 에 둔다.
   채우는 선택지는 채울 수만큼 센다(무작위 태그 5개면 5개). 넘는 화면은 순수 검사와 게임 씬 검사가 알린다(`FindTooManyChoices`).
   고를 것이 막혀 떠나는 선택지를 저절로 끼울 때 칸이 다 찼으면, 고를 수 없는 선택지를 뒤에서부터 하나 빼고 끼운다(`EventRunner.MaxChoices`).
   많은 대상에서 고르는 선택지는 고르기 화면을 쓴다
7. **선택지 칸의 밝기 변화** 인게임 화면 기획서 04 화면 공통 규칙 의 버튼 상태를 가져와
   마우스를 올리면 10퍼센트 밝게, 누르면 10퍼센트 어둡게 한다.
   고를 수 없는 칸은 밝기를 건드리지 않는다.
8. **삽화** 선택지를 고른 뒤 경우에 따라 바뀔 수 있다.
   결과에 삽화를 넣어 주면 바꾸고 비워 두면 앞의 것을 그대로 둔다.

## 기획서와 와이어프레임이 어긋나는 곳

- 문서 목차와 슬라이드 제목은 "11 이벤트 화면"인데
  와이어프레임 프레임 이름과 내보낸 이미지 파일 이름은 "12 이벤트"다.
- 와이어프레임 선택 전 화면에서 칸과 글자의 이름표가 서로 엇갈려 있다.
  `④` 는 칸이 "결과 모름", 글자가 "조건 미달"로 되어 있고 `⑤` 는 그 반대다.
  그림을 보면 둘째 칸이 조건 미달, 셋째 칸이 결과 모름이라 글자 쪽 이름이 맞다.

## 이 코드에 없는 것

이벤트 기획서가 아직 없어 그쪽이 정할 것이라 손대지 않았다.

- 이벤트 목록과 각 이벤트의 삽화, 본문, 선택지 내용
- 어느 이벤트가 나올지 고르는 규칙
- 선택지의 조건 판정과 결과 결정
- 보상 지급. 기획서대로 전투 보상과 같게 처리하므로 보상 쪽이 맡는다
- 이벤트 방에서 몬스터를 만나는 경우.
  맵 생성 규칙 기획서 04 방 목록 은 이벤트 방에서 몬스터 조우도 가능하다고 적었다
- 이벤트가 끝난 뒤 보상 화면으로 넘어가는 처리. 끝났다는 것만 알린다
