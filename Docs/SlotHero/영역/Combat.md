# Slot Hero 전투 코드

슬롯머신 작동 방식 ver. 1.1.a 와 전투 UI 및 연출 초안을 옮긴 것이다.
맵에서 일반 · 엘리트 · 보스 방에 들어가거나 이벤트가 전투를 열면 이 화면이 뜬다.

2026년 10월 25일에 만들었다. 같은 날 저장소 원본 코드(`Assets/Scripts`, `Assets/Scenes`, `Assets/Prefabs`)를 폐기했다.
원본의 전투(`NewNewCombat`)는 1.0.b 방식(예측 → 회전 → 홀드 → 재회전)이라 옮기지 않고 새로 썼다.

## 공격력

2026년 10월 25일에 정했다.

- 코인을 건 태그가 붙은 문양만 계산에 쓴다. 나머지 문양은 계산에도 재굴림에도 들어가지 않는다
- 더하는 것은 **문양의 가치**다. 태그의 값이 아니다. 문양 가치는 태그 둘의 값을 더한 것이다(물건 목록의 태그 가치)
- 공격력 = 문양 가치 합 × (중복 배수 + 코인 가중치)
- 공격은 **한 번**이다. 태그마다 따로 때리지 않는다

1.1.a 작동 예시를 이 규칙으로 다시 쓰면 다음과 같다.

| | 값 |
| --- | --- |
| 건 태그 | 해왕성. 소모 10 · 가중치 5 코인 |
| 해왕성 문양 | 섬(해왕성/토성) 7, 난파선(해왕성/명왕성) 9 |
| 문양 가치 합 | 16 |
| 중복 배수 | 2개 → 2 |
| 공격력 | 16 × (2 + 5) = **112** |

기획서의 예시는 토성 7 과 명왕성 9 를 따로 더해 130 이라 적었는데, 이 규칙으로는 112 가 맞다. 공격이 한 번이라 따로 더하지 않는다.
`CheckCombat` 이 이 112 를 확인한다.

## 붙이는 법

### 1. 설정 에셋을 만든다

메뉴 `Slot Hero > 설정 에셋 한 번에 만들기`. `Configs/Combat` 에 셋이 생긴다.

### 2. 원 그림을 만든다

메뉴 `Slot Hero > UI 스킨 만들기`. `Art/Skin/원.png` 가 원판과 코인과 태그 칸의 바탕이다.

### 3. 씬을 만든다

메뉴 `Slot Hero > 확인용 씬 만들기 > 전투 화면` 이 `14 전투 화면` 을 짓고 보기 자료로 한 번 열어 둔다.
그다음 `Slot Hero > 게임 씬 만들기` 가 그 화면을 게임 씬으로 옮기고 `GameFlow` 에 `CombatEntry` 를 붙인다.

### 4. 호출

흐름이 부른다. 직접 부를 때는 이렇게 한다.

```csharp
combatScreen.PlayerHealthLost += amount => context.TakeDamage(amount);
combatScreen.Finished += outcome => Debug.Log(outcome.Won);
combatScreen.Open(setup, icons);
```

플레이 중이 아니거나 `Instant` 를 켜면 연출 없이 한 번에 지나간다. 검사가 그렇게 실제 화면을 누른다.

## 검증

메뉴 `Slot Hero > 전투 검사`(`CheckCombat`). 2026년 10월 25일 84건 모두 통과했고, 흐름 검사(`CheckGameScene`)도 577건 모두 통과했다.

- 규칙. 112 계산, 코인 없이 32, 문양 없는 태그, 재굴림이 쓴 자리만 바꾸는지, 한 장뿐인 문양이 겹치지 않는지,
  코인 셋이 서로 다른지, 소모값과 남는 체력, 적 공격과 패배, 승리와 오버킬, 시드, 규칙 기본값, 태그 칸 차례와 누르기 범위
- 화면. 게임 씬에 창구와 화면이 물렸는지, 런 하나로 전투를 끝까지 눌러 체력이 런에 적히고 결과가 흐름으로 돌아오는지

흐름 검사(`CheckGameScene`)는 검사하는 동안만 전투 대역(`PlaceholderCombatEntry`)을 붙여 승패를 바로 고른다.
씬은 저장하지 않으므로 끝나면 원래대로다.

## 기획서에 없어 내가 정한 부분

- **소용돌이 칸은 평소 효과가 없다.** 블랙홀은 아직 기획 중이라 칸만 두었다. 누를 수 없고 올리면 "아직 효과가 없는 칸" 이라 적는다.
  유물 사건의 지평선이 있을 때만 켜지고 가장 많은 태그로 공격한다.
  1.1.a 의 "태그에 사용하지 않고 모든 릴 재굴림(공격 없음)" 은 그래서 아직 없다
- **코인 UI 가운데 작은 원은 "코인 없이" 다.** 초안에 설명이 없는 자리다.
  코인이 하나도 없거나 체력이 모자라 쓸 수 없으면 전투가 멈추므로 그 길로 두었다. 가중치 0, 소모 0 이다
- 코인은 쓰고 나서 체력 1 이 남아야 쓸 수 있다. 1.1.a 는 "소모값 이상의 체력" 이라 적었는데 그대로면 코인으로 스스로 쓰러진다.
  원본의 `PlayerCoinInventory.minimumRemainingHealth` 도 1 이었다
- 태그를 누르면 바로 공격한다. 초안 흐름도에 확인 단계가 없다
- 그 태그 문양이 하나도 없으면 칸을 어둡게 하고 누를 수 없게 했다. 0 으로 때리는 턴을 막는다
- 1.0.b 를 따라 도는 동안에는 문양 그림만, 멈춘 뒤 태그가 함께 나온다
- 원판 위에 안내 글을 두었다("코인을 고르세요", "코인을 걸 태그를 고르세요"). 초안에는 없다
- 공격 연출은 태그 색 구슬 하나와 피해 숫자, 몬스터 흔들림이다. 초안이 "구체적인 공격 모션은 논의 필요" 라 적었다
- 두 UI 전환은 흐려졌다 나타나기만 한다. 초안이 "세부 연출은 두 UI 이미지가 확정된 다음" 이라 적었다
- 전투 골드는 0 이다. 기본 보상 골드는 방 보상 규칙(`RewardRuleConfig`)이 이미 준다. 오버킬은 넘친 피해 10 마다 1 골드

## 유물

`유물 정보시트.xlsx`(유물 목록 · 유물조건 · 유물 능력)를 옮겼다. 2026년 10월 25일.
유물 정의와 효과는 `RelicConfig` 의 코드가 정본이다. `설정 에셋 한 번에 만들기` 가 에셋을 이 목록으로 갈아 끼우고
물건 목록(`RunCatalogConfig.Relics`)도 열 개로 맞춘다(`CreateDefaultConfigs.SyncRelics`). 예전 임시 유물 셋(낡은 책, 날개, 곡괭이)은 뺐다.
식별자는 `relic_` 뒤에 시트의 Num 이다(`relic_12001`). 희귀도 1 ~ 5 는 일반 ~ 전설이다.

시트는 조건 Enum 과 능력 Enum 을 번호로 잇는 범용 꼴인데, 지금 열 개가 쓰는 조합은 열 가지라
조합 하나를 효과 종류 하나(`RelicEffectKind`)로 두었다. 새 조합이 나오면 종류를 더한다.

| 유물 | 효과 | 코드 |
| --- | --- | --- |
| 제국 군기 | 화성 태그 가치 +5 | `TagValueAdd`. 문양 가치는 태그 둘의 값을 더하므로 화성 문양 가치가 5 오른다 |
| 흑요석 단검 | 코인 소모값 +10, 코인 가치 +3 | `CoinCostAdd`, `CoinWeightAdd`. 코인을 쓸 때만 든다 |
| 12개의 금화 | 코인 가치 -5 에서 시작, 같은 태그 문양 3개마다 영구 +1 | `CoinWeightFromCounter`. 쌓인 횟수는 `OwnedRelic.Stack` 에 저장한다 |
| 망치와 끌 | 첫 턴 최다 태그 문양 3개 추가 | `AddTopTagSymbols`. 게임의 모든 문양 중 그 태그를 무작위로 골라 **이번 전투 덱에만** 더한다 |
| 철제 방패 | 10 이상 피해에 -5 | `ReduceDamageTaken` |
| 사건의 지평선 | 블랙홀을 쓰면 가장 많은 태그로 공격 | `VortexAttacksTopTag`. 소용돌이 칸이 켜진다 |
| 별의 저편 | 천왕성 · 해왕성 · 명왕성 태그 2회 사용 | `ReuseSymbolsWithTag` 셋. 태그마다 따로 발동해 난파선(해왕성 · 명왕성)은 세 번 쓰인다 |
| 일식 | 내행성 -3, 외행성 +3 | `TagValueAdd` 둘. 내행성은 수성 · 금성 · 지구 |

| 속임수 주사위 | 가장 좌측 문양 1회 재사용 | `ReuseReelAt` |

2026년 10월 25일에 정한 해석.

- 문양 **재사용**은 그 문양의 가치를 한 번 더 더한다. 중복 배수(문양 수)는 그대로다. 재사용으로는 다시 발동하지 않는다(시트 비고)
- **12개의 금화**는 릴이 멈출 때마다(처음 회전과 매 재굴림 뒤) 가장 많은 태그가 3개 이상이면 +1, 런 내내 쌓인다
- **망치와 끌**로 더한 문양은 이번 전투 덱에만 들어간다
- 시트의 "Atk 단계는 매 태그마다 반복" 은 예전 태그별 공격 방식의 설명이다. 지금은 공격이 한 번이라 한 번만 든다
- 가치나 배수가 유물로 음수가 되어도 공격력은 0 아래로 내려가지 않는다

화면.

- 유물 칸에 그림이 없으면 이름을 적는다. 그림(`Relicimage_120NN.jpg`)은 아직 오지 않았다
- 12개의 금화는 칸 오른쪽 아래에 지금 고유 수치를 적고, 오를 때마다 고친다. 시트의 "-5 부분 UI 처리 필요"
- 유물 칸에 마우스를 올리면 오른쪽에 이름, 지금 값을 채운 소개문, 플레이버 텍스트가 뜬다
- 릴이 멈출 때 발동한 유물(망치와 끌, 12개의 금화)과 적이 때릴 때 발동한 유물(철제 방패)은 원판 위 안내 글에 적는다

## 이 코드에 없는 것

- 몬스터 일러스트와 공격 애니메이션. 이름을 적은 칸으로 대신한다
- 적 패턴. 1.1.a 의 "시스템적 제한" 이 무엇인지 아직 없다
- 유물 그림
- 코인 능력. 지금 코인은 소모값과 가중치뿐이다
- 이벤트가 건 부정 효과(D1 ~ D6). 창구로 넘어오지만 아직 걸지 않는다
- 사건의 지평선 없이 쓰는 소용돌이(블랙홀) 칸의 효과와 "모든 릴 재굴림"
- 아이템 상세. 유물과 코인 위에 올렸을 때 다른 화면처럼 상세 오버레이를 띄우지 않는다
